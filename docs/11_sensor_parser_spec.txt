1. 목적
--------

uart_rx가 뱉는 바이트 스트림을 센서 프레임 단위로 묶고 체크섬으로 검증해서,
유효한 측정값만 통과시킨다.

  - 센서별 전용 파서 2개로 간다 (범용 1개 대신). 두 포맷은 헤더 길이·프레임 길이·체크섬
    방식이 전부 다르고(8비트 보수합 vs 16비트 단순합) 고정 길이라, 억지로 일반화하면
    검증만 어려워진다.
  - 체크섬이 이 블록의 존재 이유다. UART는 노이즈·보율 오차로 바이트가 깨질 수 있는데,
    깨진 값을 그대로 PS에 올리면 잘못된 가스 농도로 오경보가 난다. 축사 안전 시스템에서
    "틀린 값"은 "값 없음"보다 나쁘다.

2. 블록 위치
------------

  ZE03    rx ─> [uart_rx] ─byte─> [ze03_parser]    ─> 농도/단위/레인지 ─┐
  PMS7003 rx ─> [uart_rx] ─byte─> [pms7003_parser] ─> PM1.0/2.5/10   ─┴─> AXI-Lite regfile → PS

3. 프레임 포맷
--------------

[ 3.1 ZE03 (가스, Winsen) — 능동 업로드 9바이트 ]

+--------+------------------------+
| 바이트 | 내용                   |
+--------+------------------------+
| 0      | 0xFF 시작              |
| 1      | 가스 종류              |
| 2      | 단위                   |
| 3      | 소수점 자리수          |
| 4-5    | 농도 (상위, 하위)      |
| 6-7    | 풀 레인지 (상위, 하위) |
| 8      | 체크섬                 |
+--------+------------------------+

체크섬: checksum = (~(byte1 + ... + byte7)) + 1 (2의 보수).
검증은 등가식 (byte1+...+byte7 + checksum) & 0xFF == 0 으로 구현 — 덧셈만으로 끝난다.
시작 바이트(0xFF)는 합에 넣지 않는다.

[ 3.2 PMS7003 (미세먼지, Plantower) — 32바이트 ]

+--------+----------------------------------------------------+
| 바이트 | 내용                                               |
+--------+----------------------------------------------------+
| 0-1    | 0x42 0x4D 시작 ("BM")                              |
| 2-3    | 프레임 길이 (= 28)                                 |
| 4-9    | PM1.0 / PM2.5 / PM10 (표준입자, CF=1)              |
| 10-15  | PM1.0 / PM2.5 / PM10 (대기환경) ← v1이 노출하는 값 |
| 16-27  | 입자 개수 0.3/0.5/1.0/2.5/5.0/10 µm                |
| 28-29  | 예약 / 버전·에러                                   |
| 30-31  | 체크섬 (16비트)                                    |
+--------+----------------------------------------------------+

모든 16비트 필드는 상위 바이트 먼저(big-endian).
체크섬: sum(byte0 .. byte29) 16비트 == byte30<<8 | byte31. 시작 바이트를 포함한다.

> ⚠️ 데이터시트 대조 필요: 위 포맷은 일반적인 규격 기준이다. 특히 ZE03은 변종(O3/CO/H2S)
> 마다 가스 종류 바이트가 다르고, Q&A 모드에서는 프레임이 다르다. 실물 연결 전에 보유
> 데이터시트로 ①체크섬 방식 ②능동/Q&A 모드 ③가스 종류 바이트를 반드시 확인할 것.
> 체크섬 규칙이 틀리면 모든 프레임이 버려져 값이 하나도 안 올라온다 (증상: csum_err만 증가).

4. 포트 (공통 구조)
-------------------

+----------------------+------+----------------------------------------------------+
| 포트                 | 방향 | 설명                                               |
+----------------------+------+----------------------------------------------------+
| aclk, aresetn        | in   | 동기 리셋 active-low                               |
| s_data[7:0], s_valid | in   | uart_rx의 m_data/m_valid 직결 (valid는 1클럭 펄스) |
| frame_valid          | out  | 1클럭 펄스 — 체크섬 통과, 출력 필드 갱신됨         |
| csum_err             | out  | 1클럭 펄스 — 체크섬 불일치 (프레임 폐기)           |
+----------------------+------+----------------------------------------------------+

ze03_parser 출력: conc[15:0], gas_type[7:0], unit[7:0], decimals[7:0], range[15:0]
pms7003_parser 출력: pm1_0[15:0], pm2_5[15:0], pm10[15:0] (대기환경 기준)

출력 필드는 체크섬 통과 시에만 갱신되고 다음 유효 프레임까지 유지된다 (R3).

5. 프로토콜 규칙 (R1~R7)
------------------------

+----+------------------------------------------------------------------------------------------+-------------------------------------------------+
| #  | 규칙                                                                                     | 왜 중요한가                                     |
+----+------------------------------------------------------------------------------------------+-------------------------------------------------+
| R1 | 헤더 바이트가 어긋나면 즉시 재동기. 어긋난 바이트 자신이 헤더 첫 바이트일 수 있음을 고려 | 42 42 4D ...처럼 앞에 잡음이 붙어도 놓치지 않음 |
| R2 | 체크섬 불일치 시 출력 갱신 금지, csum_err 펄스만                                         | 깨진 값이 PS로 새어나가면 오경보                |
| R3 | 체크섬 통과 시에만 출력 필드 갱신, 다음 유효 프레임까지 유지                             | PS가 언제 읽어도 마지막 유효값을 봄             |
| R4 | frame_valid / csum_err는 각각 1클럭 펄스, 동시 assert 금지                               | 상위 카운터가 중복 계수하지 않도록              |
| R5 | 16비트 필드는 상위 바이트 먼저 조립                                                      | 엔디안 뒤집힘 = 단골 버그                       |
| R6 | 프레임 사이 임의 잡음 바이트가 있어도 다음 유효 프레임을 정상 수신                       | 전원 인가 시 중간부터 수신되는 상황             |
| R7 | 리셋 시 출력 0, 상태 HUNT                                                                |                                                 |
+----+------------------------------------------------------------------------------------------+-------------------------------------------------+

6. 아키텍처 (FSM 3상태)
-----------------------

  S_HUNT   : 헤더 대기 (ZE03=0xFF 1바이트 / PMS=0x42,0x4D 2바이트, 재동기 규칙 R1)
  S_BODY   : 나머지 바이트 수집, 체크섬 누산, 필드 캡처 (임시 레지스터)
  (마지막 바이트에서 검증) -> 통과면 임시→출력 + frame_valid, 실패면 csum_err
바이트 단위로만 동작하므로 (9600 baud = 1ms/바이트) 타이밍 여유가 크다. 상태·카운터 몇 개뿐.

7. 검증 계획
------------

TB가 프레임을 조립해 s_data/s_valid로 주입한다 (파이썬 골든 불필요 — TB가 정답을 앎).

+----+--------------------------------------------+-------------------------------------------------+
| #  | 시나리오                                   | 확인                                            |
+----+--------------------------------------------+-------------------------------------------------+
| T1 | 정상 프레임 다수 (랜덤 값)                 | R3·R5 (필드·엔디안)                             |
| T2 | 체크섬 1비트 손상                          | R2 (csum_err, 출력 불변)                        |
| T3 | 프레임 앞에 잡음 바이트 삽입               | R6                                              |
| T4 | 헤더 첫 바이트 반복 (42 42 4D / FF FF ...) | R1 재동기                                       |
| T5 | 프레임 중간 절단 후 정상 프레임            | R6 복구                                         |
| T6 | 백투백 프레임 (갭 0)                       | R4 펄스                                         |
| T7 | (PMS) 길이 필드가 28이 아닌 프레임         | 무시 여부 — v1은 길이 미검사, 체크섬으로 걸러짐 |
+----+--------------------------------------------+-------------------------------------------------+

8. 완료 기준 (DoD)
------------------

각 파서 TB가 T1~T6 전부 PASS (시드 2종).

8.5 검증 기록 (2026-07-28, XSim 2025.2) — DoD PASS
--------------------------------------------------

  xvlog ..\rtl\ze03_parser.v ..\rtl\pms7003_parser.v tb_ze03_parser.v tb_pms7003_parser.v
  xelab tb_ze03_parser -s ze_sim ;  xelab tb_pms7003_parser -s pms_sim
  xsim ze_sim  -R -testplusarg '"seed=7"'
  xsim pms_sim -R -testplusarg '"seed=7"'

+----------------+------------------+--------------------------------------+
| 파서           | 시드 3종         | 결과                                 |
+----------------+------------------+--------------------------------------+
| ze03_parser    | 기본 / 7 / 12345 | TB PASS (frame_valid 26, csum_err 6) |
| pms7003_parser | 기본 / 7 / 12345 | TB PASS (frame_valid 21, csum_err 5) |
+----------------+------------------+--------------------------------------+

T1 정상·T2 체크섬손상(출력 불변)·T3 잡음·T4 재동기·T5 절단후 복구·T6 백투백 전부 통과.
PMS의 42 42 4D 재동기가 정상 동작함을 확인 (R1의 핵심).

[ TB에서 잡은 함정 (교재) ]

첫 실행에서 모든 값이 "직전 프레임의 기대값"과 비교되고 카운터가 정확히 1씩 부족했다.
RTL이 아니라 TB의 타이밍 레이스였다:
  1. 기대값을 단일 변수에 두니, 다음 프레임을 만들 때 이전 프레임의 검사가 끝나기 전에 덮어씀
     → 기대값 큐로 변경 (tb_uart_rx의 방식과 동일).
  2. 마지막 프레임의 바이트를 보낸 직후 카운터를 검사 → 그 프레임의 펄스가 아직 계수되기 전
     → settle (6클럭 대기) 삽입.

또 T4·T5처럼 결과가 원리상 모호한 시나리오(오동기가 체크섬에 걸리는지 여부는 데이터에 따라
다름)는 기대 큐에 넣지 않고 계수만 하며, 그 뒤 flush(파서를 확실히 HUNT로 되돌리는 더미
바이트)를 넣어 다음 검사를 결정론적으로 만들었다. "테스트가 가끔 실패"하는 것을 원천 차단.

9. 확정 사항
------------

센서별 전용 파서 2개, 체크섬 필수, 출력은 유효 프레임에서만 갱신, 16비트 big-endian.
PMS7003은 v1에서 대기환경 PM1.0/2.5/10만 노출 (입자 개수는 나중에 확장 — 필드 캡처
인덱스만 추가하면 됨). AXI-Lite 노출은 다음 블록.
