1. 목적
--------

베이어(Bayer) RAW 스트림 → RGB888 스트림 변환. 커스텀 ISP의 첫 영상처리 블록.

  - 라인버퍼 + 3×3 슬라이딩 윈도우 — 이후 모든 공간 필터(가우시안, 미디언, 열화상 3×3)의 뼈대가 되는 구조를 여기서 확립한다.
  - 파이프라인 전체에 백프레셔를 전파하는 첫 블록 (TPG는 소스라 출력만, regfile은 단발 응답 — 이건 스트림 통과형).
  - 경계 처리 + 프레임 말미 드레인 — 윈도우 기반 스트림 처리의 두 난제를 정면으로.

2. 블록 위치
------------

  [axis_tpg (pattern=2'b10 베이어)] ──8bit RAW──> [axis_demosaic] ──RGB888──> (5단계: 먹스/감마 → VDMA)
  [Pcam 5C CSI-2 RX (6단계~)]      ──────────────┘

단일 클럭 도메인. 시뮬은 64×48, 실카메라는 1280×720 (파라미터만 변경).

3. 파라미터 / 포트
------------------

+-------------+--------+------------------------------------------------------------------+
| 파라미터    | 기본값 | 설명                                                             |
+-------------+--------+------------------------------------------------------------------+
| H_ACTIVE    | 1280   | 라인당 픽셀 수 (라인버퍼 깊이 결정)                              |
| V_ACTIVE    | 720    | 프레임 라인 수                                                   |
| BAYER_PHASE | 2'b00  | (0,0) 픽셀의 색상: 00=R(RGGB) 01=Gr(GRBG) 10=Gb(GBRG) 11=B(BGGR) |
+-------------+--------+------------------------------------------------------------------+

+----------------------------------+----------------+----+---------------------------------------------------------------------------+
| 포트                             | 방향           | 폭 | 설명                                                                      |
+----------------------------------+----------------+----+---------------------------------------------------------------------------+
| aclk, aresetn                    | in             | 1  | 동기 리셋 active-low                                                      |
| s_axis_tdata                     | in             | 8  | 베이어 샘플 (픽셀당 1성분). v1은 8비트 고정, Pcam RAW10 확장은 6단계에서  |
| s_axis_tvalid/tready             | in/out         | 1  | 입력 핸드셰이크 (tready = 내부 진행 가능 && 다운스트림 여유)              |
| s_axis_tuser/tlast               | in             | 1  | SOF / EOL (업스트림이 R2/R3 준수한다고 신뢰 — 카운터와의 불일치는 미정의) |
| m_axis_tdata                     | out            | 24 | [23:16]=R [15:8]=G [7:0]=B (TPG와 동일 배치)                              |
| m_axis_tvalid/tready/tuser/tlast | out/in/out/out | 1  | 출력 AXIS video                                                           |
+----------------------------------+----------------+----+---------------------------------------------------------------------------+

4. 베이어 포맷 정의
-------------------

BAYER_PHASE=2'b00(RGGB) 기준, 픽셀 (x,y)의 성분은 (y[0], x[0])로 결정:

          x짝  x홀
   y짝  |  R  | Gr |     ← 짝수 행: R-G-R-G...
   y홀  | Gb  |  B |     ← 홀수 행: G-B-G-B...

일반화: cls_x = x[0] ^ BAYER_PHASE[0], cls_y = y[0] ^ BAYER_PHASE[1] → (cls_y,cls_x): (0,0)=R (0,1)=Gr (1,0)=Gb (1,1)=B.

[ TPG 확장 (pattern_sel=2'b10, 이 스펙에서 확정) ]

axis_tpg의 예약 패턴 2'b10 = 베이어 샘플링된 컬러바 (RGGB 고정):
  - 내부 컬러바 RGB(스펙 01 §6)에서 위 표의 성분 하나를 추출해 tdata[7:0]에 출력, tdata[23:8]=0.
  - 목적: 5단계 이후 실보드에서 TPG→디모자이크→VDMA 경로를 카메라 없이 검증.

5. 알고리즘 — Bilinear 보간 (3×3)
---------------------------------

윈도우 중심 (x,y), 픽셀 클래스별 (P=중심값, 이웃은 클램프된 좌표에서):

+---------------------+------------+------------------+------------+
| 클래스              | R          | G                | B          |
+---------------------+------------+------------------+------------+
| R 사이트            | P          | (좌+우+상+하)>>2 | (대각4)>>2 |
| Gr 사이트 (R행의 G) | (좌+우)>>1 | P                | (상+하)>>1 |
| Gb 사이트 (B행의 G) | (상+하)>>1 | P                | (좌+우)>>1 |
| B 사이트            | (대각4)>>2 | (좌+우+상+하)>>2 | P          |
+---------------------+------------+------------------+------------+

라운딩 규칙 (R6): 버림(truncation). >>1, >>2는 floor — 골든모델과 RTL이 동일해야 하는 계약. (반올림 개선은 나중에 골든과 함께 바꾸면 됨.)

6. 경계 정책 (R5): 좌표 클램프 (edge replicate)
-----------------------------------------------

윈도우 탭 좌표는 clamp(0, H-1), clamp(0, V-1):
  - x=0에서 "좌" := (0,y) 자기 열, x=H-1에서 "우" := 자기 열
  - y=0에서 "상" := 0행, y=V-1에서 "하" := V-1행

출력 프레임은 입력과 동일한 H×V (크롭 없음, 제로패딩 없음). 모든 픽셀이 골든과 비트 일치해야 한다 — 경계 픽셀도 예외 없음.

8. 아키텍처 개요 (구현은 RTL 주석이 교재)
-----------------------------------------

  s_axis ──> [라인버퍼 2×H×8 (BRAM)] ──┐
        └──────────(현재 행)───────────┼──> [3행 탭 + 행 클램프 먹스]
                                       │        │
                                       │   [3×1 칼럼 시프트 ×3행 + 열 클램프]
                                       │        │ 3×3 윈도우
                                       │   [클래스 디코드 + bilinear 덧셈트리]
                                       │        │
                                       └──> [출력 레지스터 (R1-safe)] ──> m_axis

핵심 설계 포인트 (코드에서 이 순서로 읽을 것):

  1. 지연 정렬: 출력 (x,y)는 입력 (x+1,y+1)이 도착해야 완성 — 클램프 덕에 "없는 이웃"은 이미 버퍼에 있는 값으로 대체되므로, 출력은 입력보다 정확히 1행+1픽셀 뒤에서 따라온다.
  2. 드레인: 마지막 입력 (H-1,V-1) 억셉트 후에도 마지막 행 출력 ~H+1픽셀이 남는다. 이때 입력 소비 없이 내부 재생(가상 row V = row V-1 클램프)으로 윈도우를 계속 전진 — s_axis_tready를 내리고 출력만 진행하는 상태. R4의 본체.
  3. 전역 CE: 모든 파이프 단은 (!m_axis_tvalid || m_axis_tready)일 때만 전진 — TPG의 R1-safe 템플릿이 "파이프라인 전체의 클럭 인에이블"로 승격되는 지점.
  4. 라인버퍼: simple dual-port, 입력 억셉트 시 write, 읽기 주소는 윈도우 열. y[0]로 두 버퍼 스왑.

지연(정보): 첫 SOF 출력까지 입력 ~H+2픽셀. 드레인 ~H+1사이클.

9. 검증 계획
------------

  - 골든: demosaic_golden.py — ① 테스트 이미지 생성(컬러바/램프/랜덤 시드) → 베이어 샘플링 → bayer_in.hex + 기대 RGB rgb_exp.hex ② --compare로 RTL 덤프 대조. 수식·클램프·버림 모두 §5-6과 비트 일치.
  - TB: 파일 스티뮬러스($readmemh)를 AXIS 마스터로 재생. 입력 valid 랜덤화(+valid_mode) × 출력 ready 랜덤화(+ready_mode) — 입력이 끊겨도(업스트림 굶김) 출력이 막혀도(다운스트림 스톨) 비트 일치해야 함. 기대값 인라인 비교 + hex 덤프(파이썬 2차 대조용). 2프레임 연속(R9).
  - 이번 TB의 새 요소: AXIS 슬레이브 프로토콜 체커 (tready 하이 중 페이로드 변경 감시 등은 TPG TB에서 이식).

전부 TB PASS + COMPARE PASS. (선택) OOC 합성 — LUT/FF/BRAM 리포트 기록.

11. 실행 방법 (확정)
--------------------

  # PowerShell, sim/ 폴더에서
  $env:PATH = "C:\AMDDesignTools\2025.2\Vivado\bin;" + $env:PATH
  xvlog ..\rtl\axis_demosaic.v tb_axis_demosaic.v
  xelab tb_axis_demosaic -s dem_sim                              # RGGB
  xelab tb_axis_demosaic -s dem_sim_p3 -generic_top '"PHASE=3"'  # BGGR
  
  # 스티뮬러스+기대값 생성 → 시뮬 → 대조 (한 세트)
  python ..\model\demosaic_golden.py --width 64 --height 48 --img bars --phase 0 --gen bayer_in.hex --exp rgb_exp.hex
  xsim dem_sim -R -testplusarg '"valid_mode=1"' -testplusarg '"ready_mode=1"'
  python ..\model\demosaic_golden.py --width 64 --height 48 --img bars --phase 0 --compare dem_out.hex
  # (--compare는 --exp 파일이 아니라 동일 인자로 재계산해 대조 — tpg_golden과 동일 방식)
  # 랜덤: --img random --seed N / 2프레임: --frames 2 + xsim +frames=2

12. 남은 결정 (없음 — 이 스펙으로 확정)
---------------------------------------

경계=클램프, 라운딩=버림, 위상=파라미터 4값, 스티뮬러스=파일 재생, TPG 2'b10=베이어 컬러바.
바꾸고 싶은 항목이 있으면 RTL 착수 전에 말할 것 (골든·TB·RTL 세 곳이 같이 움직여야 함).
