1. 목적
--------

AXI4-Stream video 프로토콜을 따르는 테스트 패턴 생성기.

  - 카메라 없이 TPG → VDMA → DDR 캡처 경로를 검증한다 (2단계).
  - 이후 모든 커스텀 블록(디모자이크, 감마, WB)의 테스트 입력 소스가 된다.
  - AXIS 핸드셰이크 / SOF / EOL 개념을 익히는 첫 블록.

2. 블록 위치
------------

  [axis_tpg] ──AXIS──> (2단계: AXI VDMA S2MM → DDR)
                       (4단계~: AXIS 먹스 → 디모자이크 → ...)

단일 클럭 도메인 (통합 시 FCLK1 150MHz, 시뮬레이션은 임의).

3. 파라미터
-----------

+----------+--------+---------------------------------------------------+
| 파라미터 | 기본값 | 설명                                              |
+----------+--------+---------------------------------------------------+
| H_ACTIVE | 1280   | 한 라인의 픽셀 수. 8의 배수여야 함 (컬러바 8등분) |
| V_ACTIVE | 720    | 프레임의 라인 수                                  |
+----------+--------+---------------------------------------------------+

시뮬레이션에서는 TB가 H=64, V=48로 오버라이드한다 (시뮬 속도).

4. 포트
--------

+---------------+------+----+-------------------------------------------------------+
| 포트          | 방향 | 폭 | 설명                                                  |
+---------------+------+----+-------------------------------------------------------+
| aclk          | in   | 1  | 클럭                                                  |
| aresetn       | in   | 1  | 동기 리셋, active-low                                 |
| enable        | in   | 1  | 1이면 프레임 생성. 0이 되면 프레임 경계에서 정지 (R5) |
| pattern_sel   | in   | 2  | 패턴 선택 (아래 §6). 프레임 경계에서만 반영 (R6)      |
| m_axis_tdata  | out  | 24 | 픽셀. [23:16]=R, [15:8]=G, [7:0]=B                    |
| m_axis_tvalid | out  | 1  | 데이터 유효                                           |
| m_axis_tready | in   | 1  | 다운스트림 수신 가능 (백프레셔!)                      |
| m_axis_tuser  | out  | 1  | SOF: 프레임의 첫 픽셀 비트에서만 1                    |
| m_axis_tlast  | out  | 1  | EOL: 각 라인의 마지막 픽셀에서 1                      |
+---------------+------+----+-------------------------------------------------------+

5. 프로토콜 규칙 (R1~R8) — 리뷰 기준
------------------------------------

+----+------------------------------------------------------------------------------------------------------------------------------------------------------+---------------------------------------------------------------------------------+
| #  | 규칙                                                                                                                                                 | 왜 중요한가                                                                     |
+----+------------------------------------------------------------------------------------------------------------------------------------------------------+---------------------------------------------------------------------------------+
| R1 | 전송은 tvalid && tready가 둘 다 1인 클럭에서만 일어난다. tvalid를 올렸으면 억셉트될 때까지 내리면 안 되고, 그동안 tdata/tuser/tlast도 바꾸면 안 된다 | AXI 기본 계약. 어기면 VDMA에서 픽셀 유실/중복 — 초보 버그 1위                   |
| R2 | tuser(SOF)는 프레임의 (x=0, y=0) 픽셀 비트에서만 1                                                                                                   | VDMA가 SOF 기준으로 프레임버퍼를 시작함. 잘못되면 화면이 어긋나거나 프레임 유실 |
| R3 | tlast(EOL)는 각 라인의 x=H_ACTIVE-1 픽셀에서만 1                                                                                                     | VDMA 라인 스트라이드 동기화 기준                                                |
| R4 | 프레임당 픽셀 수는 정확히 H_ACTIVE × V_ACTIVE                                                                                                        | 하나라도 어긋나면 VDMA 에러 또는 프레임 밀림                                    |
| R5 | enable이 0이 돼도 진행 중 프레임은 완주하고 프레임 경계에서 정지. 재개 시 새 프레임부터                                                              | 프레임 찢김(tearing) 방지                                                       |
| R6 | pattern_sel 변경은 프레임 경계에서만 반영                                                                                                            | 프레임 중간 패턴 전환 방지                                                      |
| R7 | 리셋 시 tvalid=0, 내부 카운터 초기화                                                                                                                 |                                                                                 |
| R8 | 프레임 사이 갭 없이 연속 생성 가능해야 함 (갭 삽입은 선택 기능)                                                                                      |                                                                                 |
+----+------------------------------------------------------------------------------------------------------------------------------------------------------+---------------------------------------------------------------------------------+

6. 패턴 정의
------------

BAR_W = H_ACTIVE / 8

+-------------+---------------+------------------------------------------------------------------------+
| pattern_sel | 패턴          | 정의                                                                   |
+-------------+---------------+------------------------------------------------------------------------+
| 2'b00       | 컬러바 8개    | bar_index = x / BAR_W (구현 힌트 §7 참고 — 나눗셈 금지)                |
| 2'b01       | 수평 램프     | R=G=B = x[7:0]                                                         |
| 2'b10       | 베이어 컬러바 | RGGB 샘플링된 컬러바, 샘플은 [7:0] (정의: docs/04 §4, 구현 2026-07-20) |
| 2'b11       | 단색          | 24'h80_80_80                                                           |
+-------------+---------------+------------------------------------------------------------------------+

컬러바 색 (bar_index 0→7):

+-----+--------+-----------+
| idx | 색     | RGB (hex) |
+-----+--------+-----------+
| 0   | 흰색   | FFFFFF    |
| 1   | 노랑   | FFFF00    |
| 2   | 시안   | 00FFFF    |
| 3   | 초록   | 00FF00    |
| 4   | 마젠타 | FF00FF    |
| 5   | 빨강   | FF0000    |
| 6   | 파랑   | 0000FF    |
| 7   | 검정   | 000000    |
+-----+--------+-----------+

7. 구현 힌트
------------

  1. 위치 카운터: x(0..H-1), y(0..V-1) 두 개. 오직 핸드셰이크 성공(tvalid && tready) 시에만 증가.
  2. 컬러바 나눗셈 회피: x / BAR_W를 직접 계산하지 말 것 (H=1280이면 /160 — 합성 불가는 아니지만 낭비). 대신 서브카운터 사용: bar_pos가 0..BAR_W-1을 세다가 BAR_W-1에서 bar_index(3비트)를 +1. x가 0으로 돌아갈 때 둘 다 리셋.
  3. R1-safe 출력 갱신 템플릿 (이게 핵심):

     출력을 레지스터로 두고,
     (!m_axis_tvalid || m_axis_tready) 일 때만 다음 픽셀로 갱신
     의미: "출력이 비어 있거나(valid=0), 이번 클럭에 소비된다(ready=1)"일 때만 새 값을 실어라. 이 한 줄이 R1을 구조적으로 보장한다.
  4. enable 처리: 프레임 마지막 픽셀이 억셉트되는 시점에 enable을 샘플해서 다음 프레임 진행 여부를 결정하면 R5가 자연스럽게 만족된다.
  5. 출력은 레지스터드(registered) 권장 — 타이밍도 좋고 R1 검증도 쉬움.

8. 자가 체크리스트 (제출 전 셀프 리뷰)
--------------------------------------

  - [ ] 백프레셔(tready=0) 중에 x/y 카운터가 증가하지 않는가?
  - [ ] tvalid가 1인 채 대기 중일 때 tdata/tuser/tlast가 변하지 않는가?
  - [ ] tuser가 "1클럭 펄스"가 아니라 "첫 픽셀 비트에 부착"되어 있는가? (tready가 낮으면 유지되어야 함)
  - [ ] tlast 위치가 x=H-1인가? (off-by-one 확인)
  - [ ] 리셋 직후와 enable 재개 시 첫 픽셀이 (0,0)+SOF인가?

9. 완료 기준 (DoD)
------------------

  1. tb_axis_tpg 시뮬레이션 PASS — +ready_mode=0(항상 ready)과 +ready_mode=1(랜덤 70%) 둘 다
  2. tpg_golden.py --compare COMPARE PASS — pattern 0과 1 각각
  3. (선택) Vivado OOC 합성 통과, 크리티컬 워닝 0

10. 실행 방법
-------------

  # 시뮬레이션 (Icarus Verilog 기준, sim/ 폴더에서)
  iverilog -g2005 -o tpg.vvp ../rtl/axis_tpg.v tb_axis_tpg.v
  vvp tpg.vvp +ready_mode=1        # 랜덤 백프레셔 (기본)
  vvp tpg.vvp +ready_mode=0        # 항상 ready
  gtkwave tb_axis_tpg.vcd           # 파형 보기
  
  # 골든 비교 (프로젝트 루트에서)
  python model/tpg_golden.py --width 64 --height 48 --pattern 0 --frames 2 --compare sim/tpg_out.hex
  
  # 골든 이미지 눈으로 확인 (선택, Pillow 필요)
  python model/tpg_golden.py --width 64 --height 48 --pattern 0 --png colorbar.png

[ Vivado XSim CLI (2025.2, 검증된 플로우) ]

  # PowerShell, sim/ 폴더에서
  $env:PATH = "C:\AMDDesignTools\2025.2\Vivado\bin;" + $env:PATH
  xvlog ..\rtl\axis_tpg.v tb_axis_tpg.v
  xelab tb_axis_tpg -s tpg_sim
  # 주의: PowerShell→bat 인자에서 '='가 쪼개지므로 plusarg는 반드시 '"..."' 로 감쌀 것
  xsim tpg_sim -R -testplusarg '"ready_mode=1"' -testplusarg '"pattern=0"'
  python ..\model\tpg_golden.py --width 64 --height 48 --pattern 0 --frames 2 --compare tpg_out.hex

GUI로 파형을 보려면 xsim tpg_sim -gui (또는 Vivado 프로젝트에 추가 후 top을 tb_axis_tpg로).

------------------
